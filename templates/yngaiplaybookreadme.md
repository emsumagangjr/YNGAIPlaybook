# .yngaiplaybook

> Generated by `yngorch` from YNGAIPlaybook {{VERSION}}. Edits to this
> file are replaced on the next install; the other files here are yours
> to keep as described below.

This folder holds the YNGAIPlaybook files for this project. It sits in
the project root, beside `.bare/`, outside every worktree, and is never
committed: no branch or pull request can change what is in it.

## Layout

``` text
.yngaiplaybook/
├── README.md                       this file
├── yngorchestratorconfig.yml       merge rules for /yngorchestrator
└── yngorchestratorruns/
    ├── <epic>.md                   run log, one per Epic or standalone issue
    └── <n>.lock                    run lock, present while a run writes issue state
```

## Naming

Every item here is named `<tool><purpose>`, with no separator
(`yngorchestratorconfig.yml`, `yngorchestratorruns/`), so tools sharing
the folder cannot collide. A future playbook feature that keeps files in
the project root puts them here, named the same way, and gets its own
section below.

## yngorchestrator

| File | Purpose | Owner | Overwritten by `yngorch` |
|------|---------|-------|--------------------------|
| `README.md` | this file | the playbook | yes, on every install |
| `yngorchestratorconfig.yml` | who merges each kind of pull request | you | no: written only when absent |
| `yngorchestratorruns/<epic>.md` | what each run did, so a later run resumes | the orchestrator | no |
| `yngorchestratorruns/<n>.lock` | one writer of issue state at a time | the orchestrator | no |

To change who merges, edit `yngorchestratorconfig.yml`. Each key under
`merge:` takes `required` (a person merges, the default) or `auto` (the
orchestrator merges once the work is done, every check passed and no
decision is open). A missing key, or any other value, means `required`.

| Key | Pull request |
|-----|--------------|
| `slice-to-epic` | `slice/*` into its Epic branch |
| `epic-to-main` | `epic/*` into `main` |
| `fix-to-main` | `fix/*` into `main` (standalone fixes) |

A lock left by a crashed run stays until you delete it; the orchestrator
never deletes a lock it did not create.
